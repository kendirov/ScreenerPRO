# MARKET RADAR FORMULAS

**ScreenerPRO · Market Radar** — методический документ по формулам отбора и метрикам.

| Для кого | Зачем |
|----------|--------|
| **Трейдер / ведущий** | Понять, почему бумага в «В игре», объяснить ученикам, не путать Vol x с «оборотом к среднему дню». |
| **Система / разработка** | Единый источник истины перед правкой порогов; код должен совпадать с этим файлом или явно ссылаться на него. |

**Код порогов (система):** `frontend/lib/domain/market-radar-config.ts`  
**Код отбора слоёв:** `frontend/lib/domain/market-radar-layers.ts`  
**Vol x / baseline:** `frontend/lib/domain/baseline-info.ts`, `frontend/lib/domain/intraday-baseline.ts`

---

## 1. Главная философия

Market Radar **не** показывает все акции, где «что-то происходит».

Он показывает **лучшие инструменты текущего момента** — короткие списки, а не весь рынок.

### Четыре слоя

| Слой | Смысл для трейдера |
|------|-------------------|
| **Liquidity** | Где деньги — удобно исполнять, но не сигнал на сделку. |
| **In Play** | Редкая боевая аномалия момента (0–2, редко 3). |
| **Active** | Рабочий watchlist живых бумаг (до 7). |
| **Shots** | Резкие прострелы / пробои / импульсы (до 5). |

### Главное правило

**In Play ≠** просто рост.  
**In Play ≠** просто большой оборот.  
**In Play ≠** просто пробой.

**In Play =** связка:

> ликвидность + сделки + волатильность/движение + структура цены

## 2. Базовые метрики

### Для трейдера

Это «сырьё» радара: цена, оборот, сделки, диапазон дня. Без них нельзя сравнивать бумаги между собой.

### Для системы

| Поле в API | Описание |
|------------|----------|
| `lastPrice` | Текущая цена |
| `percentChange` (`changePct`) | Изменение цены от закрытия вчера, % |
| `absChangePct` | Модуль изменения цены |
| `turnover` (`turnoverRub`) | Оборот в рублях (накопленный за сессию) |
| `tradesCount` | Количество сделок |
| `metrics.dayRangePct` | Дневной диапазон, % |
| `high` / `low` | Максимум / минимум дня |
| `open` | Цена открытия |
| `previousClose` | Закрытие прошлого дня |

### Формулы

```
absChangePct = |changePct|
```

```
dayRangePct = (high - low) / previousClose × 100
```

**Защита:** если `previousClose` отсутствует или ≤ 0 → `dayRangePct = null` (не показываем мусор).

## 3. Vol x

### Для трейдера

**Vol x** — насколько **сегодняшний оборот к текущему времени** больше обычного **к тому же времени** сессии.

Не «оборот за весь день вчера» и не «к среднему полному дню».

### Для системы

```
Vol x = оборот_сегодня(открытие → now) / средний_оборот_baseline(открытие → то же время MSK)
```

**Пример**

| Момент | Значение |
|--------|----------|
| Сейчас | 10:20 MSK |
| Оборот сегодня к 10:20 | 933 млн ₽ |
| Средний 20D к 10:20 | 300 млн ₽ |
| **Vol x** | 933 / 300 = **x3.1** |

### Правильно vs неправильно

| ✓ Правильно | ✗ Неправильно |
|-------------|---------------|
| Сегодня 10:20 / среднее 20D к 10:20 | Сегодня 10:20 / полный день вчера |
| Same-time intraday baseline | Сегодня 10:20 / средний **полный** день |
| | Подмена через `turnoverVsAverage` |

### Если same-time baseline нет

| Поле | Значение |
|------|----------|
| Vol x (данные) | `null` |
| UI | `—` |
| Подпись | `baseline ∅` |
| In Play | Vol x **не** сильный фактор → опора на **turnoverRank** |

---

## 4. Trades x

### Для трейдера

**Trades x** — насколько **число сделок к текущему времени** выше обычного **к тому же времени**.

### Для системы

```
Trades x = сделки_сегодня(открытие → now) / среднее_сделок_baseline(открытие → то же время MSK)
```

**Пример**

| Момент | Значение |
|--------|----------|
| Сейчас | 10:20 |
| Сделок сегодня | 19 600 |
| Среднее 20D к 10:20 | 10 900 |
| **Trades x** | 19 600 / 10 900 ≈ **x1.8** |

### Если истории сделок по минутам нет

| Поле | Значение |
|------|----------|
| Trades x | `null` |
| UI | `—` |
| In Play | не используем как сильный фактор |

*(На момент v1.0 intraday-история сделок в проде не подключена — Trades x чаще пустой.)*

---

## 5. Baseline

### Для трейдера

**Baseline** — с чем сравниваем «норму» в этот момент сессии. Без надёжной базы коэффициенты Vol x / Trades x не показываем.

### Режимы (система)

| Режим | Описание | Vol x / Trades x |
|-------|----------|------------------|
| **intraday-ok** | Надёжный same-time (≈20 сессий, 10m свечи MOEX) | ✓ боевые |
| **intraday-partial** | Частичная история | не reliable |
| **rough-day-avg** | Дневной avg × прогресс сессии | ✗ не честный Vol x |
| **previous-day** | Вчера × прогресс сессии | только с пометкой, не сильный сигнал |
| **missing** | Базы нет | `—` / `baseline ∅` |

### Правило

```
Боевой Vol x  ⇔  kind = intraday-ok  И  baselineIsReliable = true  И  mode = same-time
```

**Metadata (система):** объект `baselineInfo` — `mode`, `source`, `currentTime`, `baselineTime`, `isReliable`.

Примеры подписей в UI:

- `baseline: 20D 10:20`
- `baseline: 5D 10:20`
- `baseline: вчера 10:20`
- `baseline ∅`

## 6. turnoverVsAverage

### Для трейдера

Отдельная **справочная** метрика: «текущий оборот относительно **среднего полного торгового дня**».  
**Это не Vol x.** Не используйте её как «объём в моменте».

### Для системы

```
turnoverVsAverage = текущий_оборот / средний_полный_дневной_оборот (Prisma / daily history)
```

| Метрика | Горизонт сравнения |
|---------|-------------------|
| **Vol x** | Открытие → **сейчас** vs открытие → **то же время** |
| **turnoverVsAverage** | Текущий накопленный vs **целый средний день** |

**Правило:** не смешивать. В коде Vol x не fallback’ится на `turnoverVsAverage`.

## 7. Ранги внутри текущего рынка

### Для трейдера

Мы смотрим не только «много или мало», а **насколько бумага сильна относительно всего рынка прямо сейчас**.

Rank 1 = лидер по метрике среди всех акций в скринере.

### Ранги (система)

- `turnoverRank`
- `tradesRank`
- `rangeRank` (по |dayRangePct|)
- `absChangeRank`
- `volumeRatioRank` (только при reliable Vol x)

### Формула rankScore

```
rankScore = 100 × (1 - (rank - 1) / max(total - 1, 1))
```

**Пример** (100 бумаг):

| Rank | rankScore |
|------|-----------|
| 1 | 100 |
| 10 | ≈ 90.9 |
| 50 | ≈ 50.5 |

Если baseline ненадёжен, для веса «объёма» в score используется **turnoverRank**, а не Vol x.

---

## 8. Liquidity

### Для трейдера

**Liquidity** — «где деньги». Удобно исполнять, **не** обязательно есть движение.

### Для системы

```
liquidityList = top 5 по turnoverRub
```

**Tie-breaker:** при близком обороте выше бумага с большим `tradesCount`.

| Параметр | Значение |
|----------|----------|
| Лимит | 5 |
| Сортировка | turnover → trades |

Liquidity **не** сигнал на сделку.

---

## 9. In Play

### Для трейдера

**In Play** — боевой режим. Обычно **0–2** лучшие бумаги, где рынок сконцентрировал **деньги + сделки + диапазон + движение + структуру**.

Попала в In Play → не «интересно глянуть», а **аномалия момента**.

### Базовые условия (система)

| Условие | Порог |
|---------|--------|
| Торгуется, ликвидна | `isTradableLiquid` |
| Оборот | ≥ **300 млн** ₽ |
| Сделки | ≥ **10 000** |
| Структура цены | есть (см. ниже) |
| Confluence | ≥ **4** из 6 |
| inPlayScore | ≥ **85** |

### Структура цены

```
hasStructure =
  breakoutHigh
  OR breakoutLow
  OR nearHighAfterMove
  OR nearLowAfterMove
```

Детали (код): позиция в дневном диапазоне ≥ 78% / ≤ 22% + пороги % изменения (`market-radar-config.ts` → `structure`).

### Confluence (6 признаков)

| # | Признак |
|---|---------|
| 1 | `turnoverRank ≤ 10` **OR** `turnoverRub ≥ 300M` |
| 2 | `tradesRank ≤ 10` **OR** `tradesCount ≥ 10 000` |
| 3 | `rangeRank ≤ 10` **OR** `dayRangePct ≥ 1.5` |
| 4 | `absChangeRank ≤ 10` **OR** `absChangePct ≥ 1.2` |
| 5 | `volumeRatioRank ≤ 10` **OR** `volumeRatioNow ≥ 1.8` *(только при reliable baseline)* |
| 6 | `hasStructure` |

**Если baseline ненадёжен:** пункт 5 **не** даёт confluence по Vol x; вместо него засчитывается сильный **turnoverRank** (fallback).

### inPlayScore (веса)

```
inPlayScore =
  turnoverRankScore  × 0.20
+ tradesRankScore    × 0.20
+ rangeRankScore     × 0.20
+ absChangeRankScore × 0.15
+ volumeRatioScore   × 0.15   // или turnoverRank fallback
+ structureScore     × 0.10
```

### structureScore

| Ситуация | Баллы |
|----------|-------|
| breakoutHigh / breakoutLow | 100 |
| nearHighAfterMove / nearLowAfterMove | 75 |
| нет структуры | 0 |

### Финальный лимит

| Правило | Значение |
|---------|----------|
| Обычно | макс. **2** бумаги |
| Третья | только если score ≥ **92** |
| Абсолютный макс. | **3** |

## 10. Active

### Для трейдера

**Active** — короткий watchlist (**до 7** бумаг) с активностью, но **без** полной боевой связки In Play.  
Не «все активные акции рынка».

### Условия (система)

| Условие | Порог |
|---------|--------|
| Не в In Play | да |
| Оборот | ≥ **150 млн** ₽ |
| Сделки | ≥ **5 000** |
| activeConfluence | ≥ **2** |
| activeScore | ≥ **65** |

### activeConfluence (5 признаков)

| # | Признак |
|---|---------|
| 1 | `turnoverRank ≤ 20` **OR** `turnoverRub ≥ 150M` |
| 2 | `tradesRank ≤ 20` **OR** `tradesCount ≥ 5 000` |
| 3 | `rangeRank ≤ 20` **OR** `dayRangePct ≥ 0.7` |
| 4 | `absChangeRank ≤ 20` **OR** `absChangePct ≥ 0.5` |
| 5 | `volumeRatioRank ≤ 20` **OR** `volumeRatioNow ≥ 1.2` *(reliable baseline)* |

При ненадёжном baseline пункт 5 по Vol x не срабатывает; fallback — **turnoverRank**.

### activeScore (веса)

```
activeScore =
  turnoverRankScore  × 0.25
+ tradesRankScore    × 0.25
+ rangeRankScore     × 0.20
+ absChangeRankScore × 0.15
+ volumeRatioScore   × 0.15
```

### Финальный отбор

```
activeList = top 7 по activeScore (после фильтров)
```

В UI при большом числе кандидатов: *«отобрано 7 из N кандидатов»*.

---

## 11. Shots

### Для трейдера

**Shot** — «двинулось» (импульс, пробой, широкий день).  
**Shot ≠ In Play:** на тонком обороте бумага может быть Shot, но не In Play.

### Условия (система)

| Условие | Порог |
|---------|--------|
| Ликвидность | `isTradableLiquid` |
| Оборот | ≥ **80 млн** ₽ |
| Сделки | ≥ **2 000** |
| shotScore | ≥ **70** |
| Сигнал (хотя бы один) | см. ниже |

**Сигнал Shots** (любой из):

- `rangeRank ≤ 10`
- `absChangeRank ≤ 10`
- `dayRangePct ≥ 1.2`
- `absChangePct ≥ 1.0`
- `breakoutHigh` или `breakoutLow`

### shotScore (веса)

```
shotScore =
  rangeRankScore     × 0.35
+ absChangeRankScore × 0.25
+ structureScore     × 0.25
+ turnoverRankScore  × 0.15
```

### Финальный лимит

```
shotsList = top 5 по shotScore
```

## 12. Reasons

### Для трейдера

Короткая подпись **почему** бумага в слое — простым языком, не «score 86.2».

### Возможные reasons (система)

| Ключ | Подпись (пример) |
|------|------------------|
| объём / liquidity | ликвидность |
| manyTrades | сделки |
| volumeRatio | Vol x |
| tradesRatio | Trades x |
| wideRange | широкий день |
| impulseUp / impulseDown | импульс |
| breakoutHigh / breakoutLow | пробой |
| nearHigh / nearLow | у high / low |
| noBaseline | baseline ∅ |

**Плохо:** `score 86.2`  
**Хорошо:** `пробой low · оборот · широкий день`

## 13. UI-логика

### Шапка Market Radar

```
Liq N / Play N / Act N / Shot N / baseline
```

**Counts = финальные списки**, не все кандидаты.

| ✓ Правильно | ✗ Неправильно |
|-------------|---------------|
| Act **7** | Act **39** (все кандидаты) |

Если кандидатов 39, показали 7 → tooltip: *«отобрано 7 из 39 кандидатов»*.

### Пустой In Play

Текст: **«Жёстких аномалий нет»** + *«Активные: N»*.  
Это **норма**, не ошибка данных.

### Vol x / Trades x в таблице

Tooltip пример:

```
Vol x 3.2
Сегодня к 10:20: 933.9 млн
База 5D к 10:20: 291.8 млн
Ratio: x3.2
```

## 14. Защита от мусора

| Запрещено |
|-----------|
| NaN / Infinity в UI |
| Full-day baseline как Vol x |
| In Play только из-за % на неликвиде |
| 20–40 «активных» вместо top 7 |
| Дубль тикера в одном блоке |
| Reliable baseline без same-time данных |

**При ненадёжном baseline:**

- Vol x = `—`
- Trades x = `—`
- В score — **rank fallback** (turnover / trades)

## 15. Что можно менять

Калибруются в `market-radar-config.ts`:

- лимиты списков (5 / 2–3 / 7 / 5)
- пороги оборота и сделок
- пороги `dayRangePct`, `absChangePct`, Vol x
- веса score
- число confluence-признаков

### Стартовые лимиты (v1.0)

| Слой | Лимит |
|------|-------|
| Liquidity | 5 |
| In Play | 2 (макс. 3 при score ≥ 92) |
| Active | 7 |
| Shots | 5 |

### Стартовые пороги (v1.0)

**In Play**

| Метрика | Порог |
|---------|--------|
| turnover | ≥ 300 млн |
| trades | ≥ 10 000 |
| dayRangePct | ≥ 1.5 |
| absChangePct | ≥ 1.2 |
| volumeRatioNow | ≥ 1.8 |
| inPlayScore | ≥ 85 |

**Active**

| Метрика | Порог |
|---------|--------|
| turnover | ≥ 150 млн |
| trades | ≥ 5 000 |
| dayRangePct | ≥ 0.7 |
| absChangePct | ≥ 0.5 |
| volumeRatioNow | ≥ 1.2 |
| activeScore | ≥ 65 |

**Shots**

| Метрика | Порог |
|---------|--------|
| turnover | ≥ 80 млн |
| trades | ≥ 2 000 |
| dayRangePct | ≥ 1.2 |
| absChangePct | ≥ 1.0 |
| shotScore | ≥ 70 |

После изменения порогов — обновить этот документ и прогнать `pnpm -C frontend verify:market-radar`.

---

## 16. Что нельзя менять без отдельного решения

- Смешивать **Vol x** и **turnoverVsAverage**
- In Play по **одному** признаку
- Расширять In Play до **10+** бумаг
- Считать **rough** baseline reliable
- Active как полный список всех подходящих бумаг
- Убирать **rank-сравнение** с рынком
- Делать score **непрозрачным** для ведущего

---

## 17. Короткое объяснение для учеников

Market Radar ищет не просто растущие акции.

Он ищет **концентрацию внимания рынка**.

Если у бумаги одновременно:

- много денег  
- много сделок  
- большой диапазон  
- сильное движение  
- пробой или цена у экстремума  

→ может попасть в **«В игре»**.

Есть активность, но нет полной связки → **«Активные»**.  
Резко двинулась → **«Прострелы»**.  
Просто большой оборот → **«Ликвидность»**.
