# WORKFLOW — Mac M4 + Windows + Cursor + ChatGPT (для трейдера-непрограммиста)

Этот документ — «инструкция по нашему совместному рабочему процессу». Если читаешь впервые — читай по порядку, разделы короткие.

---

## 0. Краткий вывод (TL;DR)

| Машина | Что делает | Что НЕ делает |
|---|---|---|
| **Mac M4** | Cursor, ChatGPT, `pnpm dev`, браузер для скриншотов, агент | трейдинг, 7 мониторов |
| **Windows + 7 мониторов** | браузер с приложением (по LAN-адресу Mac), MOEX, обучение, торговля | Cursor, ChatGPT (отдай Mac-у) |

Связь: **GitHub** для кода, **LAN** для просмотра приложения, **`Cmd+Ctrl+Shift+4` → `Cmd+V`** для скриншотов в Cursor.

---

## 1. Почему именно так

- Cursor + ChatGPT Electron — это легко 6–10 GB RAM суммарно. На Windows-машине это и есть причина «тормозит, хотя CPU мощный».
- M4 — самый быстрый ноутбук Apple, при этом тихий и холодный. Cursor + Next.js dev на нём летает.
- 7 мониторов на Windows — это сила, которую жалко тратить на IDE. Лучше держать там реальный продукт + MOEX + обучение.

**Итог:** Mac строит и думает, Windows смотрит и торгует.

## 2. Ежедневный сценарий

### Утро (сел работать)

**На Mac:**
```bash
cd ~/Pro/Screener
./sync.sh pull          # подтянуть, что прилетело с Windows / ночью
caffeinate -d -i ./run-dev.sh
```

`caffeinate -d -i` = «macOS, не засыпай и не выключай дисплей, пока команда работает». Без этого Mac уйдёт в сон и Windows перестанет видеть dev-сервер.

**На Windows:**
- Открыть в браузере `http://<IP-Mac>:3000` (IP виден в выводе `./run-dev.sh` строка `Network:`).
- На вкладке появляется live-версия приложения с hot-reload — когда Mac меняет код, Windows сам обновляется.

### Вечер (закончил работу)

**На Mac:**
- В терминале `Ctrl+C` → dev-сервер останавливается (если что-то не закрылось — `./stop.sh`).
- `./sync.sh save` — коммит всех правок и push на GitHub.

**На Windows:**
- Ничего делать не надо.

### Сел за Windows утром (а вечером работал на Mac)

```cmd
sync.cmd pull
```

И всё, локальная копия = то, что было на Mac.

## 3. Скриншоты (главное)

Mac умеет всё то же, что Windows Snipping Tool, просто шорткаты длиннее. Запомни **один**:

> **`⌘ Cmd + Ctrl + Shift + 4`** — выделить область, картинка в буфер обмена.
> Потом в Cursor: **`⌘ Cmd + V`** — вставится в чат как изображение.

Чтобы окно «летающего превью» не появлялось 5 секунд в углу:

1. Нажми `Cmd + Shift + 5` (откроется панель скриншотов).
2. В этой панели: **Options → снять галку «Show Floating Thumbnail»**.

После этого скриншот ощущается мгновенным.

### Если скриншот хочется сделать с Windows-монитора

Три варианта, выбирай удобный:

| Вариант | Как |
|---|---|
| **PairDrop** (рекомендую) | Открыть [pairdrop.net](https://pairdrop.net) на Mac и Windows одновременно. Они увидят друг друга по LAN. Drag-and-drop картинки. Без установки, без облака. |
| **iCloud Drive / Dropbox / Yandex Disk** | Сохранять скриншоты в синхронизируемую папку. Windows: Win+Shift+S → «Сохранить как...» → в облачную папку. На Mac она появится за секунды. |
| **Не делай скриншот на Win** | У тебя на Mac тоже есть браузер. Открой там тот же URL `http://localhost:3000`, и снимай c Mac. Это часто **быстрее всего**. |

## 4. Точки отката («чекпойнты»)

> **Принцип:** агенту разрешено всё. Каждая важная веха — это чекпойнт. Откат — одна команда.

### Создать чекпойнт (когда «вот сейчас всё хорошо, запомни»)

```bash
./checkpoint.sh "before redesign"
```

→ создаст git-тег вида `cp-before-redesign-2026-05-26-1830`, запушит на GitHub.

Если не передаёшь имя — тег будет просто `cp-<дата-время>`.

### Посмотреть, какие чекпойнты есть

```bash
./checkpoint.sh list
```

### Откатиться к чекпойнту

```bash
./restore.sh                                  # показать список (ничего не меняет)
./restore.sh cp-before-redesign-2026-05-26-1830   # откатить
```

Скрипт:
1. Покажет на какой коммит откатываемся.
2. Спросит подтверждение (надо ввести `yes` — защита от случайного нажатия Enter).
3. Создаст «спасательный» тег `rescue-<время>` на текущем состоянии — чтобы откатить откат, если что.
4. Сбросит код к чекпойнту.

Чтобы Windows тоже подхватил откат — после `restore`:

```bash
git push --force-with-lease origin main
```

(скрипт сам это печатает в конце; на Windows потом просто `sync.cmd pull`).

### Откатиться на N коммитов назад (без чекпойнта)

```bash
./restore.sh HEAD~1         # на 1 коммит назад
./restore.sh HEAD~5         # на 5 коммитов назад
./restore.sh <hash>         # на конкретный коммит, hash виден в ./restore.sh без аргументов
```

## 5. Максимум автономии агенту в Cursor

Нужно сделать **один раз** в настройках Cursor:

1. **Settings → Features → Chat → Agent** → включить **Auto-run** (агент сам запускает команды, не спрашивает).
2. **Settings → Features → Chat** → включить **Enable file change auto-apply** (изменения файлов применяются сразу).
3. **Settings → Features → Codebase** → включить **Index repository** (Cursor индексирует кодовую базу для семантического поиска).

После этого агент сможет:
- Сам клонировать, ставить зависимости, запускать билд, dev-сервер.
- Сам править файлы и сразу применять.
- Сам делать коммиты (с твоего разрешения; для full-auto см. ниже).

### Полная автономия + контроль через git

Из-за того, что **каждое `./sync.sh save` — это commit**, а **каждый `./checkpoint.sh "..."` — это именованный тег**, ты в любой момент можешь:
- Посмотреть всю историю в Cursor (Source Control) или на GitHub.
- Откатить любую отдельную правку.
- Откатить всю сессию к чекпойнту до неё.

**Это и есть «максимум допущений + откат назад»** — git делает откат тривиальным, не нужно ничего бояться.

## 8. Сетевые мелочи

- **IP Mac в LAN.** Запусти `./run-dev.sh` — Next напишет `Network: http://X.X.X.X:3000`. Этот адрес Mac держит, пока он в той же Wi-Fi сети. Если Mac переехал в другую сеть — IP сменится.
- **Файрвол Mac.** При первом запуске Mac может спросить «разрешить Node принимать входящие подключения?» — нажать «Разрешить», иначе с Windows не достучаться.
- **Windows + Mac в одной сети.** Простой способ: один Wi-Fi роутер. Если у тебя их два (например, гостевой и основной) — обе машины должны сидеть на одном и том же.
- **Mac под крышкой.** Если хочешь работать с закрытой крышкой Mac, чтобы он не спал — `caffeinate -d -i ./run-dev.sh` (`-d` запрещает сон дисплея, `-i` запрещает «idle sleep» системы).

## 10. Mac путешествует: работа ↔ дом ↔ кафе

Главный принцип: **Mac везёшь с собой**. Где бы он ни оказался, всё, что нужно для разработки, работает:

| Действие | Зависит от сети? |
|---|---|
| Cursor + правка кода | нет, локально |
| `./run-dev.sh` (свой dev-сервер на Mac) | нет, Mac сам себе сеть |
| `./sync.sh save` / `pull` | нет, GitHub через интернет |
| `./checkpoint.sh` / `./restore.sh` | нет, GitHub через интернет |
| Деплой на Vercel | нет, Vercel сам собирает из main |

**Зависит от сети только одно** — прямой просмотр Mac-овского `pnpm dev` с Windows-машины по локальному IP. Это работает только когда **обе машины в одной Wi-Fi**.

### Когда Mac и Windows в разных сетях — два варианта посмотреть проект на Windows:

**1. Vercel (рекомендованно)**

В репозитории подключён auto-deploy на Vercel. Каждый `git push` в `main` → через 1–2 минуты обновляется **`https://screenerpro.vercel.app`**.

```
На Mac:   ./sync.sh save    (запушил)
На Win:   открой https://screenerpro.vercel.app/screener
```

Минусы: нет hot-reload, обновление = новый push. Плюсы: доступно из любой сети, любого устройства, никакой настройки.

**2. Tailscale (опционально, если нужен hot-reload через интернет)**

Бесплатное приложение, ставится на оба компьютера. Создаёт «виртуальную LAN» — Mac и Windows получают постоянный `100.x.x.x` IP, который не меняется при смене Wi-Fi. На Windows открываешь `http://<tailscale-IP-Mac>:3000` и видишь dev-сервер Mac независимо от того, где он физически находится.

### Локальный IP Mac в LAN меняется между сетями

На работе Mac может получить `192.168.10.83`, дома `192.168.1.42`. Это норма. После `./run-dev.sh` смотри в вывод — строка `Network:` всегда показывает актуальный адрес для текущей сети.

### Чего НЕ делать

- Не запускать `./run-dev.sh` одновременно на Mac и Windows с одним и тем же кодом. Само ничего не сломает, но запутает (две версии живут параллельно).
- Не забывать `./sync.sh save` перед уходом — иначе на другой машине не увидишь свои свежие правки.

## 11. Если что-то пошло не так — порядок действий

1. **Mac тормозит / уведомление «недостаточно памяти»:** `./stop.sh` — убьёт все осиротевшие процессы dev-сервера.
2. **Появилась подозрительная правка:** `./restore.sh` без аргументов → посмотреть список → откатиться.
3. **Windows-копия отстала от Mac:** на Windows `sync.cmd pull`. И наоборот.
4. **Build не проходит:** `pnpm -C frontend build` локально — увидеть ошибку, отдать её агенту.
5. **Совсем плохо, ничего не работает:** `./restore.sh cp-fresh-mac-setup-ready-2026-05-26-183447` — это первая «известно рабочая» точка с моего setup-а.
