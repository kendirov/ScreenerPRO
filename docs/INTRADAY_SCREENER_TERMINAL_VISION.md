# INTRADAY SCREENER TERMINAL — продуктовая доктрина ScreenerPRO

Документ фиксирует **North Star** intraday-скринера как профессионального decision terminal. Не заменяет `PRODUCT_VISION.md` (общая концепция продукта), а **углубляет** ядро — скринер акций и фьючерсов MOEX.

Связанные файлы: `PRODUCT_VISION.md`, `PROJECT_CONTEXT.md`, `docs/UI_NUMBERS_MINIMALISM.md`, `docs/MARKET_RADAR_FORMULAS.md`.

**Статус:** продуктовая доктрина (2026-07). Код и UI пока не меняются — документ задаёт направление следующих итераций.

---

## 1. North Star продукта

**ScreenerPRO — это не таблица котировок, а профессиональный intraday decision terminal** для трейдера MOEX-акций и фьючерсов.

Главная задача терминала: **за 10–30 секунд** показать, где сейчас:

| Измерение | Вопрос трейдера |
|-----------|-----------------|
| **Деньги** | Куда идёт оборот относительно нормы сессии |
| **Активность** | Где сделок и движения больше, чем «обычно в это время» |
| **Движение** | Где есть импульс, пробой, удержание экстремумов |
| **Ликвидность** | Где можно войти и выйти без штрафа по спреду и проскальзыванию |
| **Торговая ситуация** | Какой тип сетапа сейчас на инструменте — и стоит ли смотреть глубже |

Скринер — **рабочее место принятия решения**, а не витрина котировок. Каждый экран и блок должны сокращать путь от «открыл терминал» до «выбрал 1–3 инструмента для внимания».

---

## 2. Основной пользовательский сценарий

Трейдер открывает **`/screener`** или **`/screener/stocks`** и за один короткий проход должен быстро понять:

### Что происходит с рынком

- Фаза сессии: открытие, середина дня, закрытие, вне основного потока.
- Общий тон: где концентрируется оборот, есть ли лидеры по движению, «тихий» или «живой» рынок.

### Какие акции «в игре»

- Инструменты с активностью **выше собственной нормы** (оборот, сделки, диапазон) — не просто топ по абсолютному обороту.
- Почему тикер попал в фокус: **числовые причины на поверхности**, без скрытой магии score.

### Условия для сделки

- Оборот и сделки — достаточны ли для выбранного стиля (скальп / интрадей).
- Спред и ликвидность — можно ли войти без «налога» на вход.
- Статус торгов — инструмент реально торгуется, а не «есть в списке».

### Тип торговой ситуации

Теги и подписи на языке сделки:

| Тип | Смысл для трейдера |
|-----|-------------------|
| **Импульс** | Резкое движение на объёме |
| **Пробой** | Выход за значимый уровень / диапазон |
| **Удержание high/low** | Цена у экстремума сессии |
| **Объёмная аномалия** | Оборот или сделки сильно выше нормы времени суток |
| **Раскорреляция** | Инструмент ведёт себя иначе сектора / индекса / связки |
| **Позднее движение** | Активность или ход, нетипичные для текущей фазы сессии |

### Что смотреть первым

- Приоритет: **причина попадания в фокус** → ключевые 2–3 числа → детали в inspector.
- Трейдер не должен листать десятки колонок, чтобы понять «зачем мне этот тикер».

## 3. Главные продуктовые блоки

Архитектура терминала — набор **движков и поверхностей**, каждый с чёткой ролью в сценарии 10–30 секунд.

### Market Pulse

**Общее состояние рынка и сессии.**

- Фаза сессии, агрегированный тон (оборот, активные сегменты).
- Ответ на вопрос: «рынок сейчас живой или спит?» до погружения в таблицу.

*Связь с кодом:* `/screener` (Market Command Center), пульс сессии, радары — развитие в сторону единого «пульса», а не разрозненных карточек.

### In Play Engine

**Поиск инструментов с активностью выше собственной нормы.**

- Vol x, Trades x, in-play score, baseline к времени суток (MSK).
- Отделение «абсолютно ликвидного, но скучного» от «сейчас в игре».

*Связь с кодом:* `enrichMoexStocksWithInPlayMetrics`, Market Radar блок **«В игре»**, `docs/MARKET_RADAR_FORMULAS.md`.

### Situation Engine

**Присвоение тегов торговым ситуациям.**

- Импульс, пробой, high/low, объёмная аномалия, раскорреляция, позднее движение.
- Теги — **объяснение**, не декорация; за каждым тегом — проверяемое условие.

*Связь с кодом:* `inPlayTags`, Market Radar **«Прострелы / Импульсы»**, колонки и chips в таблице.

### Smart Screener Table

**Плотная таблица с фильтрами, сортировками и пресетами.**

- 5–7 колонок по умолчанию (см. `docs/UI_NUMBERS_MINIMALISM.md`).
- Пресеты: скальп, интрадей, ликвидность, in-play.
- Виртуализация, сортировка, один клик — inspector.

*Связь с кодом:* `/screener/stocks`, `/screener/futures`, `ScreenerTable`, `stockColumns`.

### Instrument Inspector

**Боковая панель по клику на инструмент.**

- Полные метрики, причины in-play, спред, оборот, диапазон, теги ситуации.
- Ссылка на карточку тикера и лаборатории при необходимости.

*Связь с кодом:* inspector в screener pages, паттерн из technical characteristics.

### Session Memory

**Сравнение текущего состояния с 20 / 40 / 60 минут назад.**

- «Что изменилось с последнего взгляда» — рост оборота, смена лидера, новый тег ситуации.
- Память сессии, не исторический бэктест.

*Статус:* продуктовый блок на развитие; placeholder в roadmap.

### Future Voice / Notes Pipeline

**Разметка трейдерских наблюдений, транскриптов и ситуаций.**

- Голосовые заметки, привязка к тикеру и моменту сессии.
- Обучающий и аналитический слой поверх терминала — **не** подмена скринера.

*Статус:* будущий pipeline; не блокирует текущий MVP терминала.

## 4. UI Direction

**Стиль:** тёмный современный терминал — минимализм, высокая плотность данных, яркие акценты **только** на важных сигналах.

### Палитра и поверхности

| Элемент | Направление |
|---------|-------------|
| **Background** | Deep navy / near black |
| **Surfaces** | Чуть светлее navy (панели, строки таблицы) |
| **Borders** | Тонкие blue-gray |
| **Primary accent** | Cyan / electric blue — фокус, выбранная строка, ключевой сигнал |
| **Warning** | Amber — осторожность, частичные данные, нестандартный режим |
| **Positive / negative** | Приглушённый green / red — изменение цены, не «кричащие» свечи |

### Типографика и плотность

- Компактная, **табличная** вёрстка с акцентом на цифры.
- Тикер и % — на поверхности; название эмитента — tooltip / inspector.
- Выравнивание чисел по разрядам; единицы (млн ₽, %, x) — явные и единообразные.

### Чего избегать в визуале

- Перегруз карточками, тенями, декоративными градиентами.
- Случайные цвета без трейдерского смысла.
- «Витринный» glass/neon там, где нужна **рабочая** таблица (лаборатории могут быть ярче; скринер — строже).

Согласование с `docs/UI_NUMBERS_MINIMALISM.md`: на поверхности 2–3 числа; остальное — tooltip / inspector; статус данных обязателен.

## 5. Что НЕ делать

| Антипаттерн | Почему |
|-------------|--------|
| **Новостной портал** | Лента новостей без связи со скринером отвлекает от решения «где торговать сейчас». |
| **Красивая витрина вместо терминала** | Дизайн ради wow-эффекта в ущерб плотности и скорости скана. |
| **Индикаторы без трейдерского смысла** | RSI/MACD на каждой строке, если не отвечают на «почему в игре» или «какой тип ситуации». |
| **Скрывать причины фокуса** | Score без расшифровки, теги без чисел — трейдер не должен гадать. |
| **Фейковые данные без статуса** | Demo / fallback / partial — только с явным `DataStatusBadge` и понятной подписью. |

## 6. Критерии качества

**Каждый новый блок должен отвечать на один вопрос:**

> *«Как это помогает трейдеру быстрее выбрать инструмент или отфильтровать мусор?»*

Если ответа нет — блок **не добавлять**.

### Чек-лист перед merge UI/фичи скринера

1. Сокращает ли это время до «понял, что смотреть» (цель 10–30 с)?
2. Видны ли **числовые причины** попадания тикера в фокус?
3. Честен ли статус данных (MOEX / fallback / оценка)?
4. Не дублирует ли блок таблицу или Market Radar без нового смысла?
5. Соответствует ли минимализму цифр (`docs/UI_NUMBERS_MINIMALISM.md`)?

### Приоритет развития (логика, не жёсткий roadmap)

1. Market Pulse + In Play + Situation — ядро decision terminal.
2. Smart Table + Inspector — основной рабочий цикл.
3. Session Memory — усиление intraday-контекста.
4. Voice / Notes — после стабилизации ядра.

## Связь с существующим кодом (без ломки)

Доктрина **не требует** немедленного рефакторинга. Текущие маршруты и компоненты остаются источником правды:

| Маршрут / модуль | Роль в доктрине |
|------------------|-----------------|
| `/screener` | Market Pulse + вход в лаборатории |
| `/screener/stocks`, `/screener/futures` | Smart Screener Table + Radar |
| `MarketRadar` | In Play Engine + Situation Engine (витрина) |
| Inspector pattern | Instrument Inspector |
| `docs/MARKET_RADAR_FORMULAS.md` | Формулы In Play / Active / Shots |

Новые итерации **выравнивают** UI и логику под эту доктрину поэтапно, без big-bang переписывания.
