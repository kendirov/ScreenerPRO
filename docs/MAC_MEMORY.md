# MAC_MEMORY — почему Mac зависает и что делать (16 GB)

Короткий гайд для не-программиста. Если Mac «крутится», тормозит или уходит в перезагрузку с отчётом **panic / watchdog** — читай это.

---

## Что означает твой panic-лог

Ключевые строки:

- **`watchdog timeout`** — система зависла настолько, что даже служебный таймер ядра не отвечал ~94 секунды. Это не «баг кнопки», это **полный freeze**.
- **`25 swapfiles` и `LOW swap space`** — оперативной памяти не хватило, macOS months/weeks писала данные на диск (swap). Когда swap кончается — всё встаёт.
- **`100% of segments limit (BAD)`** — сжатие RAM (compressor) тоже на пределе.

**Вывод:** проблема — **перегруз памяти**, а не «плохой Wi‑Fi» и не «сломанный Git».

ScreenerPRO может быть **спусковым крючком**, но корень — сочетание:

| Что ест RAM | Примерно |
|-------------|----------|
| macOS + WindowServer | 3–5 GB |
| Cursor (несколько extension-host) | 2–4 GB |
| ChatGPT / Edge / Chrome вкладки | 2–8 GB |
| **Next.js dev (Turbopack)** | 2–6 GB + **по ~worker на ядро CPU** |
| Сироты `next-server` после закрытия терминала | ×2 если запускали dev дважды |

На **16 GB** всё это вместе легко даёт 30+ GB «виртуальной» нагрузки → swap → freeze → panic.

---

## Почему «раньше было топ», а после установок dev-штук — нет

Частые причины (не обязательно все сразу):

1. **Глобально ставили Node/npm/pnpm** и копили кэш (`~/.npm` у тебя ~3 GB).
2. **Запускали `next dev` много раз** — каждый раз Turbopack поднимает пул workers; если не убить — они остаются сиротами.
3. **Эксперименты в домашней папке** (`~/package-lock.json` в корне home — мы уже удалили; Next тогда смотрел не в проект).
4. **Cursor + dev + браузер** одновременно на одном Mac.
5. **Долго не перезагружали** — swap-файлы копятся (в panic-логе было 25 штук).

Это **накопительный** эффект. Один проект не обязан быть виноват — но dev-сервер — самый тяжёлый постоянный потребитель.

## Что мы уже сделали в репозитории

| Защита | Файл |
|--------|------|
| Перед стартом убивает старый dev | `run-dev.sh` → `stop.sh` |
| Убивает всех `next-server` | `stop.sh` |
| Лимит heap Node 3 GB | `NODE_OPTIONS=--max-old-space-size=3072` |
| **Стабильный dev (меньше RAM)** | `pnpm -C frontend dev:stable` (= webpack, без Turbopack) |
| Именованные откаты | `checkpoint.sh` / `restore.sh` |

**По умолчанию `./run-dev.sh` теперь запускает `dev:stable`, не Turbopack.**

Быстрый Turbopack (если когда-нибудь понадобится и Mac свободен):

```bash
pnpm -C frontend dev
```

## Правила на каждый день (запомни 4)

1. **Один dev-сервер.** Перед работой: `./stop.sh`. Потом: `./run-dev.sh`. Не запускай второй терминал с dev.
2. **Не держи dev, когда не смотришь сайт.** Закончил — `Ctrl+C` или `./stop.sh`.
3. **Смотреть UI можно без dev на Mac:** открой `https://screenerpro.vercel.app` — после `./sync.sh save` сайт обновится сам. Dev на Mac нужен только для **мгновенного** preview при правках.
4. **Перед тяжёлой сессией в Cursor** — закрой лишние вкладки браузера и ChatGPT desktop (или оставь только в браузере одну вкладку).

## Если Mac снова тормозит (без паники)

```bash
cd ~/Pro/Screener
./stop.sh
```

Подожди 30 секунд. Activity Monitor → вкладка **Память** → «Использование swap» должно перестать расти.

Раз в 1–2 недели при ощущении «всё стало вязким» — **обычная перезагрузка Mac** (не kernel panic, просто Restart). Это сбрасывает swap.

## Безопасная уборка (раз в месяц, по желанию)

Выполнять **когда dev не запущен**:

```bash
./stop.sh
pnpm store prune
npm cache clean --force
```

Очистка кэшей macOS (осторожно, освобождает место, не трогает проекты):

- **Системные настройки → Основные → Хранилище** → рекомендации.
- Или в терминале (только кэши, не документы):

```bash
rm -rf ~/Library/Caches/pip
rm -rf ~/Library/Caches/Homebrew
rm -rf ~/Library/Caches/node-gyp
```

У тебя `~/Library/Caches` ~13 GB — часть можно сбросить через «Хранилище», не удаляя вручную всё подряд.

## Когда dev на Mac не нужен вообще

Рабочий цикл **без локального сервера**:

1. Правки в Cursor на Mac.
2. `./sync.sh save`
3. Смотришь результат на `https://screenerpro.vercel.app` (Windows, телефон, где угодно).

Так Mac почти не нагружается — остаются только Cursor и git.

---

## Красные флаги — что сказать агенту

- «Mac опять ушёл в перезагрузку» → **не запускать dev**, сначала `./stop.sh`, прислать panic если есть.
- «Нужно только посмотреть как выглядит» → **Vercel**, не `./run-dev.sh`.
- «Нужно быстро править UI» → `./run-dev.sh` (stable), **один** терминал, браузер **одна** вкладка localhost.
